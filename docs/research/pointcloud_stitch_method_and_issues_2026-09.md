# PointCloudStitch 当前流程与问题总结

最后核对日期：2026-09-18

本文是当前 PointCloudStitch 实现的调研和问题交接记录。内容依据当前源码、模块文档、`stitching_report.json` 以及既有真实数据回放结果整理。本文不等同于新的修复方案；其中的风险和未完成事项不代表已经批准的实现方向。

## 1. 当前流程总览

PointCloudStitch 的主流程由模块 30 统一编排，数据链路如下：

1. 读取输入 PLY，并完成格式、点数量、坐标有限性和范围检查；
2. 根据输入位姿和手眼标定执行坐标转换；
3. 将各帧组织为 `robot_base` 坐标下的 `RobotBaseFrame`，保留点序、源文件、来源索引和扫描比例；
4. 对相邻帧执行配准，维护严格的扫描顺序；
5. 进行平面预对齐、主平面识别和跨帧平面身份跟踪；
6. 计算实际重叠区域并生成 source/target 裁剪集；
7. 在需要时执行切向粗对齐或宽范围恢复候选搜索；
8. 依次执行三层 ICP；
9. 对结构点进行双向距离、覆盖率、点数、P95、重叠和退化检查；
10. 只有通过正式验收的 pair 才提交修正矩阵和变换后的点云；
11. 按扫描顺序累计 `registrationCorrections`；
12. 根据实际投影重叠执行 seam fusion；
13. 生成正式点云、预览、映射文件和 `stitching_report.json`；
14. 通过事务化输出保证失败或取消时不发布部分正式结果；
15. 取消使用共享 `CancellationToken`，失败和取消均保持 fail-closed。

模块职责关系：

- 模块 10：PLY 读写、输入数据处理和事务化输出；
- 模块 50：手眼和机器人坐标转换的数学实现；
- 模块 30：拼接流程编排、配准调用、seam fusion、诊断和正式输出；
- 模块 40：当前多帧配准/ICP 兼容实现及相关匹配能力；规范职责仍逐步收敛为工件位置确认；
- 模块 60：平面、边缘、ROI 和其他几何能力，不承担本次拼接流程的整体编排。

## 2. 当前采用的方法

### 2.1 输入和坐标转换

- 读取阶段支持缓存和输入元数据保留；
- 输入帧先经过有效性、范围和数量检查；
- 位姿使用 `[X,Y,Z,A,B,C]`，其中 `A=Rx`、`B=Ry`、`C=Rz`；
- 旋转约定为 `Rz(C)*Ry(B)*Rx(A)`；
- 手眼转换后统一进入 `robot_base` 坐标，后续配准不再直接使用相机坐标；
- `RobotBaseFrame` 保留 `fullPoints`、`samplePoints`、`sourceIndices`、`scanRatios` 和标定元数据。

### 2.2 平面拟合和身份跟踪

- 平缓平面优先使用原有全局 Z 高度带路径，以保持既有基线结果；
- 平缓路径无效或检测到较大倾角时，使用方向无关的确定性 RANSAC + PCA 精化；
- 当前方向无关路径的最大平面倾角为 `75°`；超过限制返回 `plane_tilt_exceeds_limit`；
- 平面模型记录法向、倾角、RMS、内点数、内点比例和拟合方法；
- 跨帧平面身份使用法向差、平面偏移，并兼容既有高度跟踪信息；
- 陡峭面若缺少足够结构特征，返回 `steep_plane_feature_insufficient`，不通过正式输出。

### 2.3 重叠区域和裁剪

- 平缓面主要使用机器人坐标下的重叠框；
- 当结构面与主平面方向差异较大时，可路由到平面局部 `u/v/n` 坐标；
- source/target crop、实际重叠点数、结构点和 ICP 输入应来自同一重叠口径；
- 宽候选应用后需要重新计算重叠和裁剪，不能继续复用宣称位姿下的旧 crop；
- 重叠保留率、候选评分和最终结构验收均需要同时考虑两侧实际点数。

### 2.4 切向粗对齐和恢复

- 平衡模式默认不总是执行昂贵的宽范围搜索；当初值未满足重叠/覆盖条件时，可自动触发切向粗对齐；
- 当前 trimmed 粗对齐目标是最近邻距离中最小的一部分，默认比例为 `25%`；
- 旧的 coverage 目标仍保留用于兼容和历史报告对比；
- 严格流程失败后，可根据失败类别进入一次恢复 retry；
- 宽结构候选默认是诊断能力，候选必须满足修正预算、真实重叠、唯一性和后续 ICP 验收；
- 恢复预算和结构验收阈值不能因候选命中而自动放宽。

### 2.5 三层 ICP

- ICP 使用三层体素级处理；
- 默认对应距离约为 `3.0 / 1.5 / 0.6 mm`；
- 保留点到平面残差，结构点和边界特征可提供额外约束；
- 首层可根据预对齐 P90 距离自适应扩大对应半径；
- 每对帧的三层 ICP 和修正矩阵提交仍按扫描顺序执行；
- ICP 结果必须通过重叠、修正范围、完成层数和结构验收后才能提交。

### 2.6 结构验收

- 正式精度门槛仍为双向结构点 `3 mm >= 0.65`；
- 同时记录 `5 mm`、`10 mm` 覆盖率、P50/P90/P95、结构点数量和实际重叠点数；
- 当前默认 `structuralCoverageOfMatched=true`，覆盖率分母是实际找到对应点的结构点子集；
- 证据门槛仍要求命中点数至少达到绝对点数和裁剪区结构点比例中的较大值；
- 命中率低于 `visibilityWarningRatio=0.25` 时当前主要置位告警，不单独拒绝；
- `structuralCoverageOfMatched=false` 可复现历史总点数分母口径；
- 退化标记、Hessian 条件比、可观测自由度和高 P95 作为诊断输出保存。

### 2.7 seam fusion 和输出

- seam fusion 按扫描方向判断相邻帧实际投影重叠；
- 在融合带中寻找互相对应点，并对核心区域执行保留判定；
- 未匹配点按当前 fail-closed 规则保留或拒绝，不发布部分融合结果；
- 并行 worker 只生成私有任务结果，所有诊断、输出和 `handled` 状态按 seam 顺序归并；
- 正式输出经模块 10 的事务接口提交，避免失败时替换旧正式文件。

### 2.8 并行和取消

- 帧读取和坐标转换可并行，结果按原始帧索引归位；
- ICP 内对应搜索可按块并行，但 pair 顺序和修正矩阵累计保持串行；
- seam fusion 的分桶、融合带和核心区计算可并行，最终提交仍按确定顺序执行；
- worker 对 Qt 隐式共享容器只使用稳定的 `const` 视图和 const API；
- 取消通过共享 `CancellationToken` 传播，任务完成或退出前不销毁捕获对象；
- `parallelEnabled=false` 或 `maxParallelTasks=1` 可退回顺序路径。

## 3. 当前已验证结果

### 3.1 `1/test_1`

- 结构点命中率约 `0.9845`；
- 命中点内双向 `3 mm` 覆盖率约 `0.8693`；
- 修正约为 `(0.7015, 1.6979, -0.6516) mm / 0.2784°`；
- 与历史基线差异约在 `0.01 mm / 0.005°` 范围内；
- 当前流程可以稳定接受。

### 3.2 `5_40/test`

- `registration_all_accepted=true`；
- `formal_output=true`；
- `merged_points=5,693,114`；
- `points_before_cross_cloud_fusion=9,125,818`；
- 结构点命中率约 `0.2246`；
- 命中点内双向 `3 mm` 覆盖率约 `0.6566`；
- 报告仍标记 `structural_validation_passed=true`；
- 输出 PLY 的 Z 直方图出现约 `821.76`、`824.50`、`802.61`、`799.87` 等多个明显峰值。

这说明输出中确实存在多个空间层，不只是 GUI 画布重复显示。

### 3.3 `6_50/test`

- 结构点命中率约 `0.3703`；
- 命中点内双向 `3 mm` 覆盖率约 `0.4989`；
- 低于正式门槛 `0.65`；
- 当前继续 fail-closed，不生成正式合并文件；
- trimmed 粗对齐可改善初始距离，但尚未把最终结构精度提升到验收要求。

### 3.4 自动化验证状态

既有记录显示 Debug/Release 目标构建和模块级 CTest 曾通过，测试覆盖了：

- 多帧配准；
- 平缓/倾斜平面回归；
- 串行与并行结果等价；
- 取消和失败回滚；
- seam fusion 输入共享副本和重复调用；
- 结构化失败和正式输出保护。

但以下验证不能用已有单测替代：

- GUI 人工冒烟；
- PageHeap/WinDbg 对真实 GUI 的首次堆损坏捕获；
- 真实陡峭夹具的完整重放；
- 现场生产数据的串行/并行同配置 A/B；
- 所有真实数据集的正式 PLY 几何验收。

## 4. 当前问题与根因证据

问题按证据强度分为已确认、高可信风险和未定论事项。

### 4.1 低可见性下的结构验收可能误放行

当前命中点覆盖率口径只在找到对应点的子集内计算精度。`5_40` 中命中率约为 `0.2246`，意味着约 `77.5%` 的结构点没有有效对应关系，但命中子集内的双向 `3 mm` 覆盖率仍达到 `0.6566`，从而满足当前正式判定。

因此，当前的“命中点内覆盖率 + 较低证据门槛”不能单独证明整帧或整重叠区域已经对齐。它可能接受局部结构对齐、整体仍包含未配准空间层的结果。

### 4.2 `5_40` 单平面输入输出两个平面的风险

该现象具有以下证据：

- 正式报告允许输出；
- 命中率明显低于正常高重叠数据；
- 输出 PLY 的 Z 直方图存在多个空间层峰值；
- ICP 诊断中出现 `degenerate=true`、较低 Hessian 条件比以及较高 P90/P95 距离；
- 正式输出仍保留了大量未能建立稳定对应关系的点。

当前不能把该问题归因于单纯 GUI 重绘。高可信解释是：局部命中子集通过了结构验收，但未命中或错误层点仍被保留到正式输出。该风险尚未通过新的整体可见性拒绝规则或现场复核解决。

### 4.3 `6_50` 仍然无法恢复

宽范围搜索能够找到较大切向候选，trimmed 粗对齐也能改善初始距离，但最终覆盖率约 `0.4989`，仍低于 `0.65`。当前保持正式阈值和 fail-closed 语义，没有通过降低门槛放行。

### 4.4 陡峭平面特征不足风险

方向无关的平面拟合和 `75°` 最大倾角路径已经实现，但陡峭平面的平移、旋转和平面内自由度仍依赖边缘、孔洞、台阶或其他非平面特征。纯平面或特征不足时应结构化拒绝，不能依赖扫描轨迹猜测平面内自由度。真实陡峭夹具的稳定性仍待现场数据验证。

### 4.5 坐标链上下方向风险

已有报告出现：

- `orientation_check.suspected_upside_down=true`；
- `net_z_coefficient≈-0.99998`。

可能涉及 `RTmatDepth2robot`、`flangeFromDepth`、位姿旋转顺序或 Z 正方向约定。当前设计只报警，不自动翻转点云，也不加入固定 Z 补偿；因此该风险不会被 ICP 参数放宽掩盖。

### 4.6 seam fusion 并行崩溃风险

历史间歇性崩溃表现为 `0xc0000005`，读取地址为 `0xFFFFFFFFFFFFFFFF`，表面故障点在 `QVector<SeamFusionDiagnostic>` 扩容。已确认的上游根因是：

- seam fusion 的并行 worker 使用 Qt 隐式共享容器的非 `const operator[]` 读取；
- 多 worker 同时触发 detach，破坏共享缓冲和堆；
- 堆损坏在后续任意分配位置暴露，不能只修补 diagnostics 扩容行。

当前代码已改为稳定 const 视图、显式捕获、worker 私有结果、future 完成后顺序归并，并增加共享副本和串并行等价测试。仍需把单测结果与真实 GUI、PageHeap/WinDbg 验证区分开来。

### 4.7 ABI 和增量构建风险

`IcpOptions`、`IcpDiagnostics` 等公共结构扩展会改变对象布局。JOM 等不完整跟踪头文件依赖的增量构建可能出现新旧 object 混用，表现为随机崩溃或异常字段。清洁的源码树外构建是必要验证条件；仅增加 `reserve()` 后不再崩溃不能证明根因已经解决。

### 4.8 性能优化的实测证据仍不完整

当前已经有帧读取、坐标转换、ICP 对应搜索和 seam fusion 的并行路径，也记录了阶段墙钟时间和 worker 时间。但不同构建配置、是否触发 retry、诊断帧是否开启等因素会显著影响总耗时，因此不能将已有单次耗时差异全部归因于并行优化。需要同配置、同输入、同选项的串行/并行 A/B 才能形成性能结论。

## 7. 结论边界

- 当前配准流程已经具备平面预对齐、三层 ICP、结构验收、恢复候选、并行和事务化输出能力；
- 当前最重要的质量风险不是“没有任何重叠”，而是低可见性时局部命中指标可能掩盖整体未对齐；
- `5_40` 的双平面输出应继续视为未解决质量风险，不应仅凭 `registration_all_accepted=true` 判定结果可靠；
- `6_50` 的拒绝符合当前 fail-closed 语义；
- 坐标链方向、真实陡峭夹具、GUI 崩溃和并行性能仍需要现场或专门工具验证；
- 本文没有批准新的阈值、补偿、自动翻转或工艺变更。
