# pointcloudview 点云处理程序

主程序：`pointcloudview.exe`

界面：`mainwindow.ui`

核心算法：`pointcloudprocessor.cpp/.h`

当前技术栈：Qt 6.8.3 + C++17 + QOpenGLWidget + OpenGL 3.3 Core。

本文档只记录当前有效功能、默认算法、问题处理、输出、验证和参数建议。机器人世界
坐标拼接、Python、CUDA、PCL、VTK 和 Open3D 不属于主程序当前功能。

## 已支持的数据和功能

- 支持 ASCII PLY、Binary Little Endian PLY 和 Binary Big Endian PLY。
- 读取顶点 `x/y/z` 和可选法向量 `nx/ny/nz`，属性按名称匹配。
- 支持打开单个 PLY，或递归扫描文件夹中的全部 `.ply`。
- 文件夹扫描结果全部显示在左侧数据源列表，点击后逐文件预览。
- 支持点云旋转、平移、滚轮缩放和重置视角。
- 支持真实点体素预处理和统计离群值去除。
- 支持 GPU Picking 精确选择三个真实点并提取 2.5D 平面。
- 支持平面边缘分割、黄色边缘选择和纯黑背景二维图片输出。
- 支持“打开扫描 JSON”后台完成手眼转换并发布当前画布；通过平面二次验证和 WObj1 后自动生成边缘 Mask 和临时工件四件套。

### PLY 第一阶段加载优化

- 主查看器后台加载统一调用共享 `pcv::detail::io::readPly`，避免应用层维护第二套解析器。
- 按 PLY header 声明的顶点数一次性分配并按索引写入，减少 `QVector` 动态扩容。
- 解析过程中同步计算有限 XYZ 包围盒，主线程不再为设置 Z 映射范围重复遍历全量点。
- 保持 ASCII、binary little-endian、binary big-endian、点顺序、法向量和错误检查不变。

### PLY ASCII 解析优化

- ASCII 坐标和法向量使用无区域依赖的快速浮点解析器，支持正负号、小数和科学计数法。
- 根据 Header 计算最后一个必需属性位置，后续颜色、强度等无关属性不再转换，只跳过到行尾。
- 错误数字、非有限值和溢出值仍会被拒绝；二进制读取路径不变。

当前画布缓存 `m_points` 是全部后续处理的唯一输入。加载或处理得到新点云后，
必须先发布到画布，再清除旧平面、边缘和选点状态。

## 默认处理流程

1. 后台读取 PLY，校验文件头、属性类型、顶点数量和数据完整性。
2. 优先读取用户本地应用数据目录中有效的 `.pcvbin`；首次解析后建立二进制缓存。
3. 将完整真实点发布到当前画布缓存并上传 OpenGL VBO。
4. 可选执行体素预处理和统计离群值去除，处理结果替换当前缓存。
5. 使用 Picking FBO 在画布选择第一组平面控制点，至少 3 点，用户点击“确定平面”结束选择。
6. 全部控制点生成初始 PCA/最小二乘平面，使用 RANSAC 排除离群点，再用 PCA/最小二乘精拟合。
7. 使用第二组三点验证第一拟合平面；通过后不替换第一平面模型。
8. 对最终平面做距离分类和连通域筛选，平面内点显示灰色。
9. 对确认平面建立 UV 栅格、二值 Mask、形态学处理和连续边界。
10. 在画布显示黄色边缘，并可输出纯黑背景二维图片。

全部耗时算法通过 `QtConcurrent` 在后台运行。工作线程不得访问 QWidget、调用
`update()`、`makeCurrent()` 或直接操作 OpenGL。异步结果必须校验
`m_canvasRevision`，过期结果直接丢弃。

## PLY 加载和缓存

### 加载规则

- 顶点属性按名称读取，不依赖固定列顺序。
- 缺少 `x/y/z`、文件头不完整、类型不支持或数据截断时拒绝加载并说明原因。
- 文件夹扫描只建立数据源列表，不自动合并或配准。
- 空点云不得发布到画布。

### 缓存位置

运行缓存、启动日志和导出文件按用途保存到用户本地应用数据目录：

```text
%LOCALAPPDATA%/PointCloudSuite/pointcloudview/
├─ cache/
├─ logs/
└─ exports/
```

单文件缓存：

```text
cache/ply_<清理后的文件名>_<绝对路径哈希>.pcvbin
```

缓存头校验版本、点数、源文件大小和修改时间。运行数据不写入源码树。

### 加载速度优化

当前主要耗时来自 ASCII 浮点解析、首次缓存写入、包围盒遍历和完整 VBO 上传。
后续优化顺序：

- 分别记录文件头、解析、缓存、包围盒、VBO 和首帧耗时。
- 解析完成后先显示，缓存改为后台原子写入。
- 解析时同步计算 XYZ 包围盒并保存到缓存头。
- 使用大块读取、换行对齐分块和 `std::from_chars` 加速 ASCII。
- 文件夹扫描后以单个低优先级任务依次预热其他 PLY 缓存。
- 可先显示真实点预览，但完整点云发布前禁用处理功能。

任何预览和降采样都不得在最终结果中使用质心或虚拟点替代真实测量点。

## 点云清理

默认参数：

| 参数 | 默认值 |
|---|---:|
| 体素尺寸 | 0.25 mm |
| 统计邻域 K | 45 |
| 标准差倍数 | 1.30 |

体素处理在每个体素中保留一个真实输入点，不生成质心。统计离群值算法使用空间
网格建立邻域，根据 K 近邻平均距离计算全局均值和标准差：

```text
threshold = globalMean + stddevMultiplier * globalStddev
```

当邻居不足时扩大搜索范围或降低实际 K。参数过严、有效邻域不足或结果为空时，
保留处理前缓存并提示用户，不得删除全部点。

## n 点平面提取

界面操作只保留：

```text
取点
放弃取点
撤销选择的点
确定平面
确定候选平面
取消确定平面
```

Esc 取消当前选择，Backspace 撤销最后一个控制点。第一组至少选择 3 个、可选择任意
数量的点，并由当前画布 GPU Picking 返回；空白位置不得选点。达到 3 点后仍可继续
取点，点击“确定平面”才结束第一组选择。第二组始终固定选择 3 点，仅用于验证。

初始平面：

```cpp
// 对全部 n 个控制点计算质心和 3x3 协方差矩阵。
// 最小特征值对应的特征向量为初始法向量。
normal = pcaSmallestEigenvector(controlPoints);
d = -QVector3D::dotProduct(normal, controlPointCentroid);
```

平面方程：

```text
normal.x*x + normal.y*y + normal.z*z + d = 0
```

法向量阈值根据当前点云包围盒计算。少于 3 点、重复、越界、非有限、近似共线或不能
同时满足最终距离容差的控制点均拒绝生成平面。

最终算法：

```text
全部控制点 PCA/最小二乘初始平面
→ 初始距离阈值候选点
→ RANSAC 内点筛选
→ PCA/最小二乘精拟合
→ 最终距离分类
→ UV/XY 连通域保留目标区域
```

全部控制点用于指定目标区域并提升初始拟合稳定性，RANSAC 用于抵抗离群点，PCA
最小特征值对应的特征向量作为精拟合法向量。RANSAC 候选及最终保留连通域均必须
包含所有控制点。结果输出平面方程、RMS 距离、候选点、平面点和连通域统计。

## GPU Picking 精度

Picking 使用独立颜色 ID + 深度 FBO：

```text
当前模型矩阵/旋转/缩放/平移
→ 当前 Viewport 和 devicePixelRatio
→ 与正常渲染一致的点大小
→ 深度测试选择最前点
→ glReadPixels 读取 ID
```

中心像素为空时可以读取 3×3 GPU 像素区域，只接受有效 GPU ID。禁止 CPU 最近点
搜索和近似反投影。普通模式保留左键旋转、右键平移和滚轮缩放。


## 边缘和二维图片

默认算法：

```text
确认平面点
→ 平面 UV 投影
→ 自适应尺寸二值 Mask
→ 闭运算
→ 开运算
→ 8 邻域边界检测
→ Marching Squares 连续轮廓
→ 黄色边缘点和边界线
```

默认参数：

| 参数 | 默认值 |
|---|---:|
| 栅格尺寸 | 0.2 mm |
| 闭运算半径 | 1 |
| 开运算半径 | 1 |
| 最大栅格数 | 4,000,000 |
| 图片超采样倍数 | 3 |

如果 0.2 mm 会超过最大栅格数，自动增大实际栅格尺寸并显示最终值，不裁剪工件。
二维图片根据平面物理尺寸自适应分辨率，背景必须为纯黑 RGB `(0,0,0)`，工件
像素单独写入，便于 OpenCV 后续处理。

黄色边缘 Mask 可以直接在三维点云画布中选择，选择结果保持当前画布真实点索引。

## 显示规则

- 普通点：当前高度色、灰阶或法向量颜色模式。
- 提取平面点：灰色。
- P1/P2/P3：更亮灰色并放大。
- 边缘点和轮廓：黄色。

点云始终使用 `GL_POINTS` 和 VBO，不使用 QPainter 全量绘制。OpenGL 资源必须在
有效上下文中创建和释放。

## 输出文件

程序当前可输出：

- 平面二维 PNG（`Format_Grayscale8`，前景 `255`、背景 `0`）；
- 与 PNG 成套的 binary little-endian 平面 PLY 和 JSON 元数据；JSON 当前 schema 为
  `sr2026-temp-workpiece-info-mvp-2`，顶层结构为 `plane/image/roi/outputs`；
- 用户本地应用数据 `cache/` 中的 `.pcvbin` 加载缓存；
- 用户本地应用数据 `logs/startup.log` 启动诊断日志。

PNG、PLY、JSON 由共享 `pcv_output` 契约 writer 写出。输出先进入临时目录，随后按
PNG、PLY、JSON 顺序成套提交；提交失败会回滚已有正式文件，任一文件失败均不报告成功。
用户选择的 `destinationDirectory` 会直接作为输出目录，不再重定向到默认任务目录。

“打开扫描 JSON”入口使用 `QtConcurrent` 后台执行；输入/契约错误使用 warning，转换、
平面和输出错误使用 critical。窗口关闭时先断开完成信号，再等待该后台任务结束。

二维图片背景为纯黑色，尺寸根据平面物理范围和实际栅格自动生成。缓存和日志属于
运行文件，不作为源码交付内容。

## 参数建议

- 统计离群值先使用 `K=45`、`1.30`；速度不足时先做代码计时，不直接降低精度。

### 2026-08-20：修复 PLY 读取器 Debug 栈保护区损坏

- 原因：阶段五把 `binaryWorkerCount` 追加到公共 `PlyReadOptions` 和 `PlyReadResult`。
  Qt Creator 增量构建可能只重建读取库而保留旧的应用目标文件；新旧结构体大小不一致时，
  MSVC 会在返回 `PlyReadResult parsed` 时报告 `Run-Time Check Failure #2`，表现为
  “Stack around the variable 'parsed' was corrupted”。
- 修复：二进制线程数恢复为 `ply_reader.cpp` 内部实现，不再改变公共结果结构体 ABI；
  诊断测试改为验证自动路径。完整重建后，紧凑 Binary XYZ 快速路径和通用 PLY 回退路径均保持不变。
- 构建修复：`pointcloudview` 和 `pointcloudstitch` 的处理器源文件通过 CMake
  `OBJECT_DEPENDS` 显式依赖 `ply_reader.h`。即使本机 MSVC 中文 `/showIncludes` 未生成有效
  `.obj.d` 文件，读取接口变化也会强制重新编译调用方，禁止新读取库与旧对象文件混合链接。
- 验证：Qt 6.8.3 / MSVC x64 Debug 主程序构建通过，`ply_reader_tests` 通过，目标样本点数和
  XYZ 边界保持 `4,741,478` 点及原值。
